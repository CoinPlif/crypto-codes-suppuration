# Коды маркировки — объединение и сверка

Streamlit-приложение для работы с Excel-выгрузками кодов маркировки (DataMatrix):
склейка нескольких файлов в один и сверка выданных кодов с отчётом об
использовании.

## Возможности

### Объединение файлов

Загружаете несколько `.xlsx`/`.xls`-файлов — они склеиваются вертикально,
столбец под соответствующий столбец. Показывает:

- статистику по строкам/колонкам, в том числе разбивку по файлам;
- предупреждение, если у какого-то файла число колонок отличается от
  остальных (недостающие заполняются пустыми значениями);
- количество повторяющихся кодов и опцию удалить дубликаты (оставляя первое
  вхождение);
- превью результата и выгрузку в `.xlsx`.

### Сверка использованных кодов

Загружаете отдельно выгрузку всех выданных кодов и отчёт об использованных —
приложение делит выданные коды на использованные и неиспользованные и даёт
скачать все три набора. Сравнение идёт по первым 31 символу кода (`01` + GTIN
+ `21` + серийный номер), поэтому криптохвост, который есть в выгрузке заказа,
но отсутствует в отчёте об использовании, сравнению не мешает.

## Структура проекта

```
crypto-codes-suppuration/
├── app.py                     # точка входа, навигация по страницам
├── ui.py                      # общие UI-элементы (загрузчик, превью, скачивание)
├── merger.py                  # чтение и склейка Excel-файлов
├── reconciler.py              # сверка выданных кодов с отчётом об использовании
├── views/
│   ├── merge_files.py         # страница «Объединение файлов»
│   └── reconcile_codes.py     # страница «Сверка использованных»
├── tests/
│   ├── test_merger.py
│   └── test_reconciler.py
└── requirements.txt
```

Страницы лежат в `views/`, а не в `pages/`: `st.navigation` сам строит меню
из явного списка, и каталог `pages/` включил бы вторую, автоматическую
навигацию поверх неё.

## Установка и запуск

```bash
python -m venv .venv
.venv\Scripts\activate       # Windows
pip install -r requirements.txt

streamlit run app.py
```

## Технические детали

- **Расширению файла верить нельзя**: выгрузки заказов иногда приходят с
  именем `.xls`, хотя внутри лежит обычный xlsx (zip-архив). Движок pandas
  выбирается по сигнатуре файла (`merger.detect_engine`), а не по расширению.
- **Шапки в файлах нет** — первая строка уже данные, столбцы сопоставляются
  по позиции (`header=None`).
- **`dtype=str` обязателен** при чтении: иначе ведущий ноль в GTIN пропадёт,
  а коды со спецсимволами превратятся в числа или даты.
- **Сравнение кодов по 31 символу**: в выгрузке заказа за значащей частью
  кода (GTIN + серийный номер) идёт криптохвост, которого нет в отчёте об
  использовании — сверка отрезает его перед сравнением.
- Excel-файлы с примерами кодов, лежащие в корне репозитория, в git не
  попадают (см. `.gitignore`) — это рабочие данные, а не часть проекта.
